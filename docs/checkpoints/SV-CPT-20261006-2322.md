## Architecture rules that must remain

- Never depend on one giant HTTP upload.
- Long operations must be resumable and bounded.
- Packages must be portable and inspectable.
- Same-domain recovery and cross-domain cloning are both first-class use cases.
- Never perform naive replacement that corrupts PHP serialized data.
- Production restore must have a verified pre-restore recovery point.
- Local/remote storage must remain abstractable.
- Runtime data stays outside plugin source under wp-content/sitevault/.
- Runtime storage must be protected from direct web access.
- Destructive operations require explicit confirmation and preflight validation.
- Preserve the currently executing SiteVault plugin during restore/rollback.
- Never release a restore lock until the transaction or its compensation is in a known safe state.
